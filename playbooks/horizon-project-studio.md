# Horizon Project Studio | Fluxos e produto

Objetivo: converter requisitos em entregas completas, sem perder funcionalidades ao melhorar a estética.

Procedimento:
1. Identificar plataforma alvo e artefato exigido (web, desktop, APK Android nativo, backend LAN etc.).
2. Documentar ações por usuário, permissões, navegação, estados e endpoints do projeto já existente.
3. Priorizar tarefas operacionais: mínimos toques para pedido, fila clara na cozinha, contingência do caixa, supervisão de gerência.
4. Dividir UX, frontend, backend e QA em entregas rastreáveis e integráveis.
5. Testar a jornada ponta a ponta com dados descartáveis, conferir duplicidades, presença, rotas e histórico.
6. Não confundir mockup com implementação, APK com navegador, dados fictícios com produção.

Não introduzir novo framework ou reconstruir backend se o projeto vigente não exigir. Alterações são revisadas antes da main.
